# Quest Desktop

Исследование следующего видеотракта **4K60 / виртуальный монитор Windows**:
[архитектура, проверка оборудования и критерии приёмки](docs/video-streaming-design.md).
Текущая рабочая сборка пока использует описанный ниже JPEG-прототип.

Самостоятельное VR-приложение для Meta Quest 3: экран Windows-ПК в passthrough,
в пространстве или на HUD. Исходная настройка Unity/OpenXR и создание OVRCameraRig
адаптированы из локального проекта Quest Hand Streamer. Код сбора данных, трекинга рук,
ЭМГ, записи и прежние сетевые протоколы не используются; исходный проект не изменяется.
Свой Android ID: `com.miandic.questdesktop`, свои настройки и ПК-сервер.

## Возможности

- Подключение по локальному IP или публичному статическому IP/DNS.
- TLS 1.2, обязательная проверка SHA-256 сертификата и случайный токен доступа.
- Поток JPEG 4:4:4, качество 97 по умолчанию, исходное разрешение монитора.
- Экран неподвижен в пространстве во время сессии либо следует за головой как HUD.
- Независимые размеры и позиции для режимов, поворот экрана в пространстве,
  прозрачность HUD от 0 до 100%, сохранение настроек.
- Управление руками без контроллеров: касание указательным пальцем, прямой захват
  щипком/сжатой кистью и дистанционный луч со щипком.
- Перемещение за края, размер за углы, появляющиеся справа ползунки яркости и HUD alpha.
- Показ фактических fps и полезного битрейта в HUD; скрытие/возврат меню.

## ПК: установка и запуск

Windows, Python 3.11 или новее. Из корня репозитория в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r pc-host\requirements.txt
.\.venv\Scripts\python.exe pc-host\setup_host.py --lan-host 192.168.1.10 --remote-host 203.0.113.10
.\.venv\Scripts\python.exe pc-host\host.py
```

Замените оба IP своими. `203.0.113.10` — пример, не рабочий адрес.
`setup_host.py` создаёт `pc-host/private/` с сертификатом, закрытым ключом,
токеном и файлом подключения для шлема. Не перезаписывает существующие ключи.
Файлы этой папки исключены из Git. Не передавайте `connection.json` посторонним:
он предоставляет доступ к просмотру экрана. Сервер передаёт выбранный монитор целиком.

Другой монитор: `host.py --monitor 2`. Выбор монитора выполняется на ПК.
Максимальное качество: `host.py --quality 100`. Для слабой сети:
`host.py --quality 90 --max-width 1920 --fps 30`. `--max-width 0` сохраняет
исходное разрешение, `--fps` задаёт верхнюю границу, а не гарантированную частоту.
Поддерживается один зритель; остановка сервера — Ctrl+C.

Для LAN разрешите входящий TCP 47990 на ПК и исключите LAN из VPN.
Для интернета пробросьте TCP 47990 на роутере на этот ПК, если ПК находится за NAT,
и разрешите порт в брандмауэре. Белый IP относится к внешнему интерфейсу сети;
внутренний IP ПК желательно закрепить DHCP reservation. Дополнительный сервер не нужен.
Если роутер не поддерживает NAT loopback, в домашней сети выбирайте LAN.

## Quest: сборка и настройка

Unity **6000.3.28f1**, Android Build Support, SDK/NDK/OpenJDK.
Откройте `QuestDesktop` в Unity Hub, дождитесь импорта пакетов.

1. Меню **Desktop → 1. Настроить проект для Quest 3**.
2. **Desktop → 2. Создать сцену**.
3. **Desktop → 3. Собрать APK** → `QuestDesktop/Builds/QuestDesktop.apk`.
4. Установите APK через Meta Quest Developer Hub / ADB, запустите приложение один раз.
5. Скопируйте файл подключения:

```powershell
$adb = 'C:\Program Files\Meta VR Developer Hub\resources\bin\adb.exe'
& $adb install -r QuestDesktop\Builds\QuestDesktop.apk
# После первого запуска приложения:
& $adb push pc-host\private\connection.json /sdcard/Android/data/com.miandic.questdesktop/files/connection.json
```

В HUD нажмите **Reload config**, выберите **LAN / Internet**, затем **Connect**.
Сертификат проверяется по закреплённому SHA-256 даже при самоподписанном сертификате.
При замене ключей заново загрузите `connection.json` на шлем.
IP можно изменить цифровой клавиатурой HUD; DNS, порт и ключи задаются файлом.

**HUD / МИР** над экраном переключает привязку; **РЯДОМ** подносит экран в область,
доступную для прямого касания. Для перемещения захватите край щипком или сжатой кистью;
угол — для изменения размера с сохранением пропорций. Прямой захват также позволяет
повернуть экран кистью. В режиме HUD поворот остаётся привязан к голове.
Издалека наведите луч руки на край/угол, удерживайте щипок и двигайте рукой.
При перемещении лучом движение кисти к себе/от себя меняет глубину размещения.

Поднесите палец к правой стороне экрана или наведите туда луч: появятся вертикальные
ползунки яркости изображения и прозрачности HUD. Проведите пальцем по ползунку
либо захватите его лучом со щипком. Прозрачность HUD меняется от 0 до 100%; яркость
изображения — от 10 до 100%. В пространстве ползунок HUD alpha неактивен.
Это яркость изображения приложения, не системная подсветка Quest.

Кнопки меню нажимаются прямым касанием с подходом к поверхности и отводом пальца
после нажатия либо наведением луча и щипком. **МЕНЮ** над экраном показывает/скрывает
компактную панель подключения. Дополнительный жест: повернуть ладонь к лицу,
удержать около 0,3 с и сделать щипок, не наводясь на элементы управления.
Подробности: [управление руками](docs/hand-interaction.md).

**Recenter** возвращает экран перед лицом. После перезапуска или смены tracking origin
используйте Recenter: постоянные пространственные якоря между сессиями не реализованы.
Углы, края и панель управления сохраняют видимость даже при полностью прозрачном HUD.
Контроллеры и автоматический выбор взглядом для управления не требуются.
При снятии шлема соединение закрывается; для возврата нажмите Connect.
Для автоматического подключения по LAN при запуске добавьте `"autoConnect": true`
в `connection.json` (по умолчанию выключено).

## Задержка и качество: границы реализации

Это первая реализация потока, **не аппаратный H.264/HEVC/WebRTC**.
Каждый кадр кодируется независимо, без chroma subsampling (важно для текста).
Сервер захватывает новый кадр только по запросу после декодирования предыдущего:
нет растущей очереди захвата или воспроизведения. Используется TCP_NODELAY.
На Quest JPEG декодируется через Android BitmapFactory в сетевом рабочем потоке;
основной поток загружает готовые RGBA-пиксели в отдельную текстуру и переключает буферы.
Активная текстура HUD не пересоздаётся при получении каждого кадра, а геометрия экрана
обновляется только при изменении параметров или разрешения. В редакторе остаётся LoadImage.
Это программное декодирование JPEG, не аппаратный видеодекодер.
TCP при потере пакетов ждёт повторной передачи. На высоких разрешениях возможны просадки VR и высокий битрейт;
частота ограничена суммой захвата, кодирования, передачи, декодирования и RTT.
Для WAN этот транспорт менее эффективен, чем аппаратный видеокодек по UDP.

Предельно низкая задержка и высокая частота при исходном 4K **пока не подтверждены**.
JPEG даже с quality=100 не является lossless. Метрики HUD показывают скорость
декодирования и полезный битрейт, а не измеренную задержку от ПК до глаза.
Для рабочего места с 4K/60+ следующий этап — аппаратный захват/кодирование на ПК
и нативный аппаратный декодер на Quest с транспортом WebRTC; выдавать текущий JPEG
за такой конвейер было бы неверно.

Звук и управление мышью/клавиатурой ПК в этот проект не входят.
Данные рук используются только для локального интерфейса; сбора/записи/передачи
кинематики и связи с ЭМГ-проектом нет.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются реальный TLS handshake и pin сертификата, токен, передача нескольких
JPEG, границы протокола, дробление TCP, исходное разрешение и JPEG 4:4:4.
Тестовый захват синтетический и не обращается к экрану пользователя.
Результаты сборки и аппаратных проверок: [docs/validation.md](docs/validation.md).

Для Development APK есть локальная диагностика по ADB: `device-state.json` в папке
данных приложения и одноразовые команды `device-command.json`. Они доступны только
в отладочных сборках, не открывают сетевой порт и не содержат токенов.
Повторить аппаратный прогон: `.\.venv\Scripts\python.exe tests\check_device.py`
при установленном APK, загруженном connection.json и работающем ПК-сервере.
Снимки экрана и измерения сохраняются в исключённой из Git `.device-check/`.

API декодирования: [Unity LoadImage](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/ImageConversion.LoadImage.html).
TLS: [Python ssl](https://docs.python.org/3/library/ssl.html).
