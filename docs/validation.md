## 13.11.2026 — QDS2 / APK 0.2.0, локально без Quest

Новый GPU/NVENC → encrypted UDP/FEC → MediaCodec external Surface путь собран
Unity 6000.3.28f1, Android ARM64/IL2CPP/Vulkan, **0 ошибок**. Шлем отключён;
результаты прежних аппаратных проверок ниже не относятся к новому Surface-слою.

- 12 Python/Java тестов пройдены: существующий TLS/JPEG и новый QDS2, auth rejection,
  GCM tampering, replay/limits, FEC, reordering/duplicates и точный APK Java receiver на JVM.
- Unity RunAndBuild: TLS legacy regression, defaults migration старого connection.json,
  мир/HUD/opacity, полный набор hand regression в landscape и portrait.
- 4K HEVC loopback NVENC→UDP→NVDEC, 120 с: 60.0 decode FPS после прогрева,
  без steady drops. Реальный desktop Full HD: около 54.7 FPS.
- Проверены HEVC 2560×1600, H.264 portrait, смена размеров в одной сессии,
  восстановление при искусственной потере 0.1% UDP (около 59.2 FPS).

## Обновление управления руками, 12.11.2026

### Исправления после проверки пользователем

Пользователь подтвердил работу луча и сообщил об отказе прямого управления,
затем о мерцании/чёрных полосах у краёв HUD. По журналу исходной версии:
20 действий, из них 19 лучевых и 1 прямое, без poke.

Исправлено:

- При ближнем наведении учитывается кончик указательного пальца; при сведении пальцев
  цель сохраняется до 0,3 с, вместо переключения на ray из-за смещения середины щипка.
- Объём ближнего взаимодействия расширен с обеих сторон поверхности.
  Касание проверяет пересечение отрезка между кадрами, включая пропущенную фазу контакта.
- Временное падение общей уверенности кисти при закрытии щипка не блокирует прямую
  работу при продолжающемся валидном трекинге; потеря трекинга по-прежнему отменяет захват.
- JPEG на Android декодируется в рабочем потоке через BitmapFactory. Обмен пикселями
  выполняется блоками через direct ByteBuffer, без поэлементного JNI/C# копирования.
  Используются две текстуры; геометрия/родитель HUD не меняются при каждом видеокадре.
- При autoConnect включено переподключение после пробуждения приложения.

Программно прошли также новые регрессионные случаи: смещение пальцев при закрытии
щипка, временная низкая уверенность и быстрое пересечение поверхности кнопки.
На Quest в новой версии реально зафиксированы `poke: МЕНЮ` и `direct pinch: Edge 1`;
диагностика показала 3 прямых действия, включая 2 poke. Это действия пользователя,
не синтетическая подстановка в диагностике.

Пользователь подтвердил после установки: **«Прямое управление работает, мерцания нет»**.
Финальная сборка также установлена и запущена: TLS Connected, 1920×1080,
ошибок Unity/AndroidRuntime после запуска не обнаружено. В одном свежем диагностическом
снимке: декодирование в рабочем потоке 23,16 мс (BitmapFactory 20,68 мс), интервал
кадра Unity 13,79 мс. Это единичный замер, не средняя частота и не end-to-end задержка.
Во время финальных замеров Quest уснул, поэтому повторяющиеся старые диагностические
снимки не используются как итоговое измерение производительности. В новой диагностике
добавлена метка `sampledAtUtc`, чтобы явно отличать остановившееся приложение от свежих данных.
Из-за нестабильности USB установка/отладка выполнялась по локальному ADB Wi-Fi.

- Отдельный источник UI-поз рук, OpenXR skeleton, Hands Only, HIGH; в APK проверено
  разрешение `com.oculus.permission.HAND_TRACKING` и feature `oculus.software.handtracking`.
- Параметры экрана убраны из сетки кнопок. Добавлены четыре угла resize, захват четырёх
  краёв, поворот при прямом захвате, появляющиеся сбоку brightness/HUD alpha sliders.
- Поддерживаются прямой щипок/сжатая кисть, касание кнопок и слайдеров указательным пальцем,
  луч со щипком. При потере трекинга захват отпускается и требует разжатия перед новым захватом.
- `DesktopValidation.Run` прошёл: прямое перемещение, grip и вращение, ray move/resize,
  противоположный угол при resize, HUD move при перемещении головы, poke debounce,
  прямой слайдер яркости, ray alpha от 0 до 1, потеря трекинга и эксклюзивное владение экраном.
- Пять Python-тестов сети также прошли. Android APK собран без ошибок и установлен на Quest;
  поток 1920×1080 продолжает работать. Новые элементы управления видны на снимке compositor.
- На устройстве исправлена ошибка IL2CPP stripping для визуальных курсоров: вместо
  `CreatePrimitive(Sphere)` используется собственная mesh без зависимости от SphereCollider.
- Первоначальное подтверждение управления взглядом относится к старой версии. Результаты
  последующих реальных ручных взаимодействий и найденных дефектов приведены выше.

Инструкция: [управление руками](hand-interaction.md).

## Проверка на Quest 3, 12.11.2026

Quest 3, Android SDK 34, OS incremental 52641960034500520; OpenXR, 72 Гц.
ПК Ethernet 192.168.0.136, Quest Wi-Fi 192.168.0.181, порт TCP 47990.
Маршрут Quest → ПК проверен: wlan0, мимо VPN. Новая сборка установлена и запущена.

- Реальный TLS-поток экрана ПК получен и декодирован на Quest: 1920×1080,
  JPEG Q97 4:4:4, без уменьшения разрешения.
- Снимки compositor подтвердили passthrough, правильную ориентацию экрана и HUD alpha.
- Через локальные команды Development APK проверены World/HUD, смена родителя экрана,
  увеличение/уменьшение размера, перемещение HUD, прозрачность, скрытие/показ меню,
  recenter, отключение и повторное подключение.
- Пользователь подтвердил: экран и меню видны, кнопки выбираются взглядом.
- Исправлена ошибка управления взглядом: head-locked меню нельзя было выбрать поворотом головы.
  Для gaze меню теперь закрепляется в пространстве; с контроллером следует за головой.
- В журнале процесса после запуска не обнаружено Unity Error / AndroidRuntime Error.
  Есть предупреждения SDK о неподдерживаемых необязательных OpenXR-функциях.

20 снимков диагностических показателей с интервалом около 1 секунды после прогрева:

| Показатель | Результат |
|---|---:|
| Частота потока, медиана | 11,5 кадра/с |
| Минимальная частота в выборке | 8 кадров/с |
| Полезный битрейт, медиана | 26,09 Мбит/с |
| Декодирование JPEG, медиана единичных замеров | 23,54 мс |
| Интервал кадра Unity, медиана единичных замеров | 25,59 мс |

Это не измерение end-to-end задержки и не средняя частота VR-рендера.
Поток работает, но JPEG/LoadImage на главном потоке не удовлетворяет цели плавного
экрана с минимальной задержкой. Требуется аппаратное кодирование/декодирование видео.
Внешняя сеть/WAN, контроллер Touch и end-to-end задержка пока не проверены.
На шлем загружен отдельный LAN-конфиг с autoConnect=true; ПК-сервер оставлен запущенным
для дальнейшей проверки пользователем. Публичный IP в конфиге ещё не задан.
Локальные измерения и снимки находятся в `.device-check/` и исключены из Git.

Для повторной проверки Unity (после установки `.venv` из корневого README):

```powershell
& 'C:\Program Files\Unity\Hub\Editor\6000.3.28f1\Editor\Unity.exe' -batchmode -quit -projectPath QuestDesktop -executeMethod QuestDesktop.EditorTools.DesktopValidation.Run -logFile unity-validation.log
```

Эта проверка создаёт одноразовый TLS-сервер на loopback со случайным портом,
передаёт синтетическое изображение и удаляет временные тестовые ключи.

Оставшиеся расширенные проверки:

- выбор всех кнопок контроллером, длительную удобность управления взглядом;
- сохранение положения при tracking-origin reset, перемещениях и повторном надевании;
- граничные размеры и альфа 0/0.5/1;
- реальную частоту и отсутствие рывков VR при 1080p, 1440p и 4K;
- задержку высокоскоростной камерой: одновременно снять таймер на ПК и его изображение в линзе;
- LAN и отдельную внешнюю сеть, остановку сервера, неверный pin/токен,
  снятие шлема, восстановление после потери сети;
- достаточную полосу интернета и поведение при потерях TCP.

Сохранённые world-координаты относятся к tracking origin текущей сессии.
Для восстановления физического места между сессиями нужен отдельный spatial anchor.
